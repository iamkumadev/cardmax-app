CardMax Documentation

A responsive HTML template for a gift-card exchange product — landing page, auth flow, dashboard, and a full sell flow, all on one design system.

Overview

CardMax is built with plain HTML, one shared static CSS file, and vanilla JavaScript — no build step, no framework, no npm install required. Open any file directly in a browser and it works.

Every page shares one visual language: the die-cut "ticket stub" component, a three-typeface system (Fraunces / Space Grotesk / IBM Plex Mono), and a CSS-variable-based color system with a working light/dark mode.

Getting started

There's no build step. Unzip the download and open landing.html (or any page) directly in a browser, or serve the folder with any static host — Vercel, Netlify, GitHub Pages, or a plain Apache/Nginx server all work as-is.

To deploy on Vercel: import the folder as a project, framework preset "Other", no build command, output directory .

Customizing colors & fonts

Every color in the template is a CSS variable, defined once at the top of css/styles.css: 

:root {
  --emerald: 47 111 78;   /* primary action color */
  --gold: 201 162 39;     /* reward / bonus accent */
  --coral: 255 107 74;    /* errors, destructive actions */
  ...
}
html.dark { /* dark mode overrides of the same variables */ }

Change a value there and it updates everywhere that color is used — no need to touch individual pages. Values are space-separated RGB triplets (not hex) so opacity utilities like bg-emerald/10 work correctly.

Fonts are set near the top of the same file under .font-display / .font-ui / .font-mono. Swap the Google Fonts <link> in each page's <head> and update these three declarations to change typefaces globally.

Swapping in real brand logos

This template ships with no real brand logos or trademarks. Gift-card tiles use a brand-neutral monogram system instead — an initial on a deterministic color from the palette, generated in JavaScript at runtime (see the markColor() function near the top of the script block on index.html, sell.html, and landing.html).

If you're deploying this for a real store with rights to specific brand marks, replace the generated monogram markup with an <img> tag per brand. Do not source logos from a live third-party API (favicon services, etc.) in a production or resold product — license or create the artwork directly.
